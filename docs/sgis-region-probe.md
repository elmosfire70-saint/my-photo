# 코드집 대조와 지역 판정 시험

앱과 분리된 읽기 전용 시험 도구다. 사용자 사진/DB를 읽지 않으며 원본 ZIP과 도형을 수정하지 않는다. 기존 엄격 위상 검사의 exit 2 및 `accepted=false`를 성공으로 바꾸지 않는다.

## 코드집 대조

공식 ZIP의 `3. 코드집/1. 행정구역별 격자코드 매핑(adm_grid_mapping).xlsx`를 번들 Python의 openpyxl 3.1.5로 읽었다. 실제 시트는 `시도-격자` A3:B19와 `시군구-격자` A3:B252다. 코드는 숫자 셀이지만 비교할 때 문자열로 보존하고 중복·빈 코드·잘못된 타입을 거부한다. 원본 수식은 실행하지 않으며 엑셀 파일을 재저장하지 않는다.

- 시도 17개의 코드와 한글 명칭은 경계 DBF와 전부 일치한다.
- 시군구 격자표는 250개다. 공통 코드의 전체 이름(시도명 + 시군구명)은 모두 일치하지만, 경계의 `31051 부천시 원미구`, `31052 부천시 소사구`, `31053 부천시 오정구` 대신 `31050 경기도 부천시`가 있다.
- `statistics_code.xlsx`는 통계 항목 식별자 표다. 행정구역 경계 명칭표로 대체하지 않는다.

격자 매핑의 집계 범위 또는 시점 차이 가능성을 구분하지 못했으므로 어느 파일이 오류라고 단정하지 않는다. 이번 분류 레지스트리는 경계 DBF의 `BASE_DATE=20250630`과 동일한 코드/명칭을 사용한다. 격자표를 맞추려고 경계를 합치거나 일반구를 누락시키지 않는다.

`check_sgis_codebook.py`의 exit 0은 위의 **불일치까지 예상대로 재현됐음**을 뜻한다. `exact_match=false`는 그대로 출력한다. 두 자료가 완전히 일치했다는 뜻이 아니다. 파일 SHA-256·CRC는 기존 고정 ZIP 검사를 재사용한다.

## 판정 규칙

`LocalRegions.lookup(longitude, latitude, datum, accuracy_m)`은 로컬 개발용 Python API다. 앱이 이 API를 실행하는 기능은 아직 없다.

- 위경도와 명시한 측위 오차는 유한 숫자여야 한다. bool/NaN/무한대/범위 초과·음수 오차는 거부한다.
- 측지기준 문자열이 WGS84로 확인되지 않으면 `datum-unverified`이며 임의 변환하지 않는다.
- 측위 오차 또는 PROJ 변환 정확도가 불명확하면 `accuracy-unknown`이며 좌표 자체에 해당하는 구역도 후보만 반환한다.
- 검토 폭은 명시한 측위 오차 + PROJ가 보고한 변환 정확도다. 예를 들어 시험의 5m + 1m는 6m다. 이것은 오차 상한/확률/경계 정확성 보증이 아니라 명시한 입력에 기반한 보수적 검토 기준이다. 법적 경계 정확성이나 원본 GPS 오차의 독립 검증은 없다.
- 유일한 시군구 내부이며 외곽/구멍 경계까지의 거리가 검토 폭보다 크고 그 폭 안에 다른 구역도 없을 때만 `inside`와 `match`를 반환한다.
- 검토 폭 안에 외곽·공유 경계·구멍·다른 구역이 있으면 `boundary-uncertain`과 후보만 반환한다. 검토 폭과 거리가 같아도 확정하지 않는다. `match`는 null이다.
- 충분히 떨어진 영역 외부는 `outside`다. 바다·해외를 최근접 구역에 강제로 넣지 않는다. 변환 불가능한 유효 위경도는 `projection-unavailable`로 구분한다.
- 시도는 별도 시도 폴리곤 판정을 혼합하지 않고, 판정된 시군구의 검증된 상위 2자리 코드로 결정한다. 따라서 두 계층의 극미세 면적 차이를 임의 도형 보정으로 제거하지 않는다.

공간 트리와 정확한 도형 거리 연산을 사용한다. 후보 출력은 코드순으로 정렬하며 입력 도형 순서에 따라 첫 구역을 선택하지 않는다. PROJ 네트워크는 끄고 grid를 자동 다운로드하지 않는다. 현 단계는 도형 내 점 판정이며 실측 지도 정확도/GPS 오차/100만 건 성능을 보장하지 않는다.

## 재현 명령과 검사

```powershell
# 코드집 분석은 openpyxl이 포함된 번들 Python을 사용한다.
& 'C:/Users/elmos/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -B tools/check_sgis_codebook.py .cache/korea-boundaries/sgis-20250630.zip
runtime/geo-audit/Scripts/python.exe -B tools/probe_sgis_regions.py --self-test .cache/korea-boundaries/sgis-20250630.zip
```

두 명령은 각각 exit 0으로 통과했다. 코드집 검사에는 명칭 불일치·중복·누락/타입 오류 감지 시험이 포함된다. 분류 검사는 합성 경계/외부/구멍/겹침/순서 변경 19건, 실제 경계의 대표 지역 5곳·바다/해외·부천 일반구 3곳, 측지기준/오차 미확인과 잘못된 입력을 검사한다. 합성 지점이지 사용자 GPS가 아니다.

경계 로딩을 기존 공간 검사와 공유하도록 추출했다. 공통 로더는 시도 17/시군구 252개의 코드 대응·링 해석·유효 도형을 별도로 검사한다. 기존 합집합/차집합 연산과 허용오차는 바꾸지 않았다. 수 분짜리 전국 위상 계산은 이번에 반복하지 않았으며 이전 결과를 새 검사 완료로 표시하지 않는다. 앱 코드를 변경하지 않아 WPF 회귀 검사도 실행하지 않았다.

앱 적용 전에는 C# 경계 계층/로컬 데이터 로드와 EXIF 측지기준·측위 오차의 출처를 연결하고, 후보/확정 표시 및 기간+지역 검색을 검증해야 한다. 배포 데이터 출처·이용조건 표시도 남아 있다.

공식 API 근거는 [Shapely STRtree](https://shapely.readthedocs.io/en/stable/strtree.html)와 [pyproj Transformer](https://pyproj4.github.io/pyproj/stable/api/transformer.html)다. 코드집 원천은 [공공데이터포털 SGIS 패키지](https://www.data.go.kr/data/15129688/fileData.do)이며 고정 해시는 기존 확보 기록을 따른다.
